# 表达形式与保真检查

选择能减少当前理解障碍的最简单形式。偏好、设备和无障碍需要影响可用性；学习表现决定是否继续使用。

| 内容与问题 | 首选形式 | 设计要求 | 何时换一种方式 |
|---|---|---|---|
| 全章讲什么 | 导航或提纲 | 写明主问题及各部分作用，按需展开 | 导图只有标题，无法回答关系问题时加论证图 |
| 抽象概念 | 概念卡与正反例 | 保留必要条件；反例尽量只改变关键条件 | 例子很生动但说不出定义时返回术语 |
| 易混概念 | 对照表 | 同一维度比较定义、条件、例子和边界 | 维度过多时保留最能区分的项目 |
| 因果与反馈 | 因果图 | 箭头有含义，假设与已证实关系分开 | 原文只有相关性时改画关联或候选解释 |
| 论证与证明 | 论证图或分步推导 | 前提、推理依据、结论、异议可区分 | 图遮蔽重要细节时保留逐步文字 |
| 步骤与选择 | 流程图或决策树 | 输入、动作、结果、分支条件清楚 | 需要动作技能时增加实际练习 |
| 空间结构 | 标注示意图 | 部件、位置、功能对应，说明比例省略 | 静态图无法表达变化时用分镜 |
| 数值比较 | 图表 | 单位、坐标、基线、数据来源明确 | 没有数据时用定性图，避免编造数值 |
| 变化过程 | 分镜或可暂停动画 | 一次突出关键变化，允许回看状态 | 阅读者跟不上时减少变化并加静态关键帧 |
| 条件改变的后果 | 交互模拟 | 有模型依据；先预测、单变量操作、解释反馈 | 无法定义可靠模型时改用情境对照 |
| 人物选择与处境 | 案例、对话或故事 | 目标、约束、行动、后果对应原文 | 个案被误当普遍规律时回看证据 |
| 通勤预习或回顾 | 短音频或讲解脚本 | 保留主问题、条件和回查位置 | 密集公式或精细论证改用可定位文本 |

## 图文制作

图承载关系，短说明靠近对应节点。每张图回答一个明确问题；密度过高时拆成总览与局部。颜色、形状或线型有一致含义，同时提供文字标签，避免只靠颜色辨识。小图可用 Mermaid，精确排版可用 SVG，需要操作才用 HTML。使用适合当前界面的可见呈现，文件附打开入口。

交付图前逐项核对每条关键连线是否受原文支持；有意简化的关系应明确。生成交互时检查计算与状态转换是否符合模型、控制是否可用、重置是否有效、文字是否可读。模拟显示的是模型结果，不是现实已经发生的事实。

## 一段内容的最小转换示例

材料：“所有满足 A 的对象都满足 B。”

- 短解释：A 足以推出 B；B 本身不足以推出 A。
- 表示：`A → B`，箭头标“蕴含”。
- 教学例子：正方形 → 矩形。
- 反例：长宽不等的矩形满足 B，却不满足 A。
- 检验题：某个对象不满足 B，它能满足 A 吗？说明理由。

教练在检验模式中问完等待回答，随后依据回答补缺口。解释模式可以直接讲完整推导。这个例子展示的是教学结构，不应用它替换书中不同含义的 A 和 B。
