# 故事型视觉 PPT

把内容转化为观众能理解、记住和复述的画面。内容决定画面：每页先确定核心观点、理解它的视觉结构，以及观众应记住的一句话。

## 默认设置与输入

- **默认横版 16:9，PNG 目标 1920×1080。** 参考图为竖版也不改变默认；仅在用户明确要求时使用 9:16、1080×1920。
- 默认风格：电影级写实数字艺术 + 高级信息图 + 现代演示设计。默认中文、现代中文无衬线字体。
- 默认交付：可编辑 PPTX、逐页 PNG、完整演讲备注、页面结构清单、视觉提示词。用户只要分镜或设计指南时按该范围结束。
- 先读取用户给出的全部原稿和图片。长稿分段读完，记录章节与段落编号；文件无法读取时明确指出缺失内容，不能根据标题补写原文。
- 从上下文推断受众、演讲目标、时长、使用设备和页数；只询问真正影响设计且无法推断的信息。缺少原稿时可以先出设计方案；只有主题时，将后续内容标为新创作，不能声称忠实改编。
- 内容是演讲观看、课后阅读还是社交传播，决定信息密度。默认按演讲观看设计，补充细节放备注。

## 1. 建立内容地图

完整阅读后，输出 `content-analysis.md`：总主题、受众、目标、章节结构、主要论点、案例与证据、最终行动建议。

每节提取五项：核心观点、论证逻辑、具体案例、情绪基调、观众收获。区分事实、原作者观点、真实案例、假设情境、推论和新增解释。用章节/段落编号建立可回查的来源映射。

发现事实疑点、逻辑跳跃或争议结论时，单列“待核实”，保留作者原意并提出修订建议。专业公式、金融数据、技术架构与产品能力需要可靠来源支撑；必要时查证并记录链接与日期。视觉隐喻不作为证据，参考图文字也不作为事实来源。未经解决的疑点应保留标注，不能悄悄改写成确定结论。

完成标准：每个原文小节均有五要素记录；未覆盖、无法读取或待核实内容均显式列出。

## 2. 按语义规划分镜

使用 [分镜与交付模板](references/templates.md) 生成 `storyboard.md`。一个核心观点通常一页；独立论点、重要案例、复杂因果和关键结论按需拆页，不按自然段或固定字数机械切分。

每页填写：页码、章节与来源、核心观点、页面类型、画面故事、视觉隐喻及其对应关系、准确的页面文字、构图与留白、演讲备注、观众收获、待核实项。

| 类型 | 目标与视觉结构 | 适合内容 |
|---|---|---|
| A 故事场景页 | 人物与环境形成冲突，视线/动作引导到结果 | 开场、案例、困境、选择 |
| B 观点冲击页 | 强标题、一个隐喻、大面积留白 | 核心结论、转场、金句 |
| C 知识解释页 | 准确的流程、层级、因果、循环或系统图 | 模型、工作流、技术原理 |
| D 对比决策页 | 同一组维度对照，保留取舍与适用条件 | 策略、风险收益、前后变化 |
| E 路径行动页 | 起点、关键节点、步骤顺序与目标 | 学习路线、实施方案、行动 |
| F 总结框架页 | 汇总已讲概念及关系 | 章节复盘、演讲结尾 |

人物→情境→冲突→选择→结果是可选叙事结构，不要求每页凑齐。抽象模型优先准确结构图；不强塞人物。不同类型交替形成节奏，但不为凑齐六类而制造内容。

参考竖版海报时，先读 [案例转译](references/case-studies.md)，把长图中的主张、解释、行动拆成横版页面。保留语义和视觉语言，重新构图；不拉伸、硬裁或缩小整张长图塞入一页。

完成标准：原稿所有核心论点有页面承接；重复内容与有意省略的细节有说明。**默认先展示分镜，获得确认后再进入视觉样稿，不批量生成图片。** 用户已明确授权自主完成时，记录该授权并自行检查推进，不重复索取确认。

## 3. 用三张样稿确定视觉系统

阅读 [视觉规范](references/visual-system.md)，建立 `style-guide.md`，固定配色语义、字体、人物外观、材质、光影、信息框与图标语言、标题位置规则及画幅。

先做三张实际样稿：A 故事场景页、C 知识解释页、B 观点冲击页。优先从已规划页面选取；原稿不适合某类时只做不新增事实的风格试样，标明不计入正式页数。样稿包括背景和最终文字叠加，不能只用提示词代替视觉验证。

检查故事与观点是否相符、文字是否清楚、专业程度、三页是否像同一套作品，以及构图是否有变化。默认展示三页并确认风格后再批量制作；已有自主完成授权时自行验收，记录选择依据。

完成标准：三种代表页可预览，风格基准明确，发现的问题已修正。

## 4. 逐页生成与组装

使用环境可用的图像生成工具制作场景；如有 imagegen skill，按其要求调用。每页使用模板中的完整提示词，单独生成并检查，复用风格基准和必要的人物参考。实际尺寸以工具输出为准；提示词写 16:9 不等于输出已满足尺寸。

背景优先无文字。标题、中文要点、数字、公式、代码和专业图表用 PPT 原生文本、形状或原生图表叠加。结构图的节点与连线应可编辑，不能把整个页面截图作为唯一对象冒充可编辑 PPT。

组装前探测当前可用的 PPTX 创建与渲染能力，可使用已安装的 PptxGenJS、python-pptx 或演示工具。使用支持备注写入的方式，明确设置页面比例。所需依赖不可用时说明具体缺口；仍完成可执行的分镜、文案、提示词与素材清单，但标注“未完成 PPTX/渲染”，不把 HTML、PDF 或图片合集冒充 PPTX。

把**原稿对应段落完整放进对应页备注**，并与新增讲述建议、来源和核实提示分区。跨页段落按语义分配，保证全稿可回查，避免每页重复整篇原稿。刻意省略的附录等在覆盖清单中说明。

每页生成后检查主体、文字安全区、结构关系、可读性；失败只重做对应页。保存背景原图与生成提示词，更新 `progress.md` 中各页状态（分镜/样稿/背景/组装/验收），便于恢复。

## 5. 渲染验收与交付

渲染最终 PPTX 的每一页为 PNG，检查最终排版而非只看背景。按 [分镜与交付模板](references/templates.md) 填写 `qa-report.md`：

1. 内容：原文覆盖完整；观点、事实、假设清楚；没有无依据的数据、因果或绝对化结论。
2. 视觉：快速看懂核心观点；隐喻对应准确；人物、结构图和装饰均服务内容。
3. 演示：实际文字无错字、溢出、遮挡；图表数字、公式和代码准确；按投影或手机观看尺寸检查。默认安全边距 5%—8%。
4. 一致性：配色、字体、材质与人物统一；构图和明暗节奏有变化。
5. 文件：PPTX 可打开，文本与关键图形可编辑，备注存在；页数、编号和 PNG 一一对应，画幅及导出像素正确。

无法渲染时明确写“未完成视觉验收”，交付现有文件和剩余缺口。完成标准：问题逐页修复，交付文件确实存在，最终答复提供路径并说明实际验证结果。

## 调用示例

- “用 story-ppt 把这篇文章做成故事型 PPT，先给我分镜。”
- “参考这几张海报做电影感 PPT，默认 16:9，给我可编辑 PPTX。”
- “按已确认分镜制作三张样稿：故事、知识解释、观点冲击。”
- “这次用于手机口播，改成 9:16，重排布局并预留字幕区。”

用户明确选择 HTML 交互形式时可衔接 web-slide，继续沿用本 skill 的内容映射与视觉叙事规则，但交付格式以用户要求为准。
