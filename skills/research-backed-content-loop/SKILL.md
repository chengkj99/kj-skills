# Research-backed Content Loop

把内容生产从“让 AI 写一篇文章”，升级为一条可以回查、复用和继续生长的闭环。

本技能是**总控编排器**，不重复其他技能的专业规则。根据任务实际需要，路由到选题、洞察、调研、写作、作者风格、插图、发布和知识沉淀能力；不要为了展示流程而机械调用全部技能。

## 核心闭环

```text
真实问题 / 已有素材
  → 检查已发布内容与本地知识
  → 用户问题与外部证据
  → 核心洞见和边界
  → 正文生产
  → 作者视角 + 用户视角评审
  → 证据与配图逐一对应
  → 发布稿与过程资产
  → 知识沉淀决策
  → 下一篇连载
```

## 使用边界

使用本技能：

- 用户给出一个困惑、现象或想法，希望完成调研、洞察、成稿和配图。
- 用户提供文章草稿，要求核验时效、去 AI 味、补研究图、连接知识库并规划下一篇。
- 用户希望公开一篇真实案例，展示内容如何从想法进入知识库并产生下一轮内容。
- 用户明确要求一条完整内容生产闭环，而不只是写一版文字。

不要使用本技能：

- 素材和角度已经确定，只需写正文：使用 `content-creator`。
- 只需调整为康健本人语气：使用 `kangjian-skill`。
- 只需去除已有文字中的 AI 痕迹：使用 `humanizer-zh`。
- 只需做公众号封面、摘要、转发文案或草稿发布：使用 `wechat-publish-kit`。
- 只需把讨论写入个人 Wiki：使用 `wiki-doc-sink`，并服从目标 Wiki 的本地规范。

## 开始前：先确定交付边界

从对话和现有文件中提取以下信息，能合理推断时不要重复追问：

- 内容形态：公众号、短视频、小红书、知识星球或系列策划。
- 目标读者：谁会看，他们正在卡在哪里。
- 作者目标：为什么现在写，想建立什么判断或信任。
- 当前输入：真实经历、用户原话、评论、草稿、研究报告、截图、课程或知识库材料。
- 交付范围：只出正文，还是包括配图、发布包、知识沉淀和下一篇。
- 事实边界：哪些是作者亲历，哪些是外部证据，哪些仍待验证。

如果目标仓库有 `AGENTS.md`、`CLAUDE.md`、`SCHEMA.md` 或内容生产协议，先完整阅读并以本地规则为最高落地依据。

## 阶段一：检查已有内容，避免凭空立题

先搜索本地知识库、已发布内容、待写队列和已有草稿。

在 `kj-llm-wiki` 中做公众号或连载内容时，优先检查：

- `HOME.md`、`wiki/index.md`；
- `wiki/playbooks/topic-bank/series-planning.md`；
- `raw/studio/funnel/transcripts/`；
- `raw/studio/funnel/formatted/`；
- `raw/studio/funnel/published/`；
- `raw/studio/funnel/backlog/manual/` 与 `queue.md`。

明确当前内容属于续集、方法篇、案例篇、升级篇还是新系列。记录重复风险和与上一篇的连接。

需要系统选题时使用 `ai-programming-topic-planner`。不要换一个标题重复已经发布的观点。

## 阶段二：找到用户真正的问题

不要把作者想讲的主题直接当成用户问题。优先寻找：

1. 用户自己的原话、评论、搜索问题或对话；
2. 作者反复遇到的真实场景；
3. 本地资料中的失败记录和阻力；
4. 外部社区、调查或研究中可核验的共性。

把观察与证据分开：

- “我看到几位读者这样问”是观察；
- 有范围、样本和来源的调查才是研究证据；
- 没有数据时，诚实写成个人判断，不编造“很多人都……”。

从现象中寻找机制和反常识判断时，使用 `phenomenon-insight`。产出必须包含边界：这个判断在什么情况下不成立。

## 阶段三：建立证据账本

当文章包含数据、论文、报告、产品能力、年份、模型名称或可能过期的信息时，读取 `references/evidence-visual-protocol.md`。

为重要主张记录：

- 主张是什么；
- 来自作者经验、用户观察还是外部来源；
- 来源名称、链接、发布日期或更新时间；
- 证据能够支持到什么程度；
- 是否存在地域、样本、自报数据或模型版本限制；
- 正文如何用普通人的话表达；
- 是否需要对应配图。

时效敏感内容必须查询当前资料。若具体模型和年份不是论证重点，优先写长期有效的能力判断；若历史版本不可省略，要说明它只代表当时实验条件。

需要完整行业或技术调研时使用 `industry-best-practices`；只需核验少数关键主张时做轻量来源核查，不要把文章写成调研报告。

## 阶段四：收敛一个核心洞见

动笔前先写清四句话：

```text
读者通常以为：
真正的问题可能是：
我用什么经历或证据支持：
读者看完可以怎么做：
```

核心洞见应解释机制，而不只是描述现象。全文只保留一个主判断，其他材料都为它服务。

## 阶段五：完成正文

把已经确认的读者问题、洞见、证据账本和真实素材交给 `content-creator` 完成正文。

如果作者是康健，或用户要求“像我写的”，再使用 `kangjian-skill` 做作者语气门禁。不要让 `humanizer-zh` 和 `kangjian-skill` 反复重写同一篇文章；只有仍存在明显模板腔、排比腔、空泛过渡时，才用 `humanizer-zh` 做局部诊断。

写作时遵守：

- 不补造作者经历、用户反馈、数据或立场；
- 专业术语第一次出现时，紧跟一句人话解释；
- 把抽象判断落到真实任务、动作或后果；
- 先让读者看到与自己有什么关系，再讲作者的方法；
- 引用研究是为了支撑判断，不是展示“查了很多资料”。

## 阶段六：让证据和配图一一对应

文章使用研究报告、关键数据、流程关系或抽象机制时，读取 `references/evidence-visual-protocol.md`，建立“主张—来源—图片”对应表。

按优先级处理：

1. 原报告有清晰可用的图：优先引用或合规重绘。
2. 有真实数据但没有合适图片：生成数据图，并标明来源与统计口径。
3. 只有概念关系：生成原创流程图或示意图，明确写“示意图”，不要伪装成实验结果。
4. 纯叙事段落：没有视觉增益时不强行配图。

优先使用 `content-illustrator` 完成流程图、对比图和关系图；超出其能力时再选择合适的可视化或图像工具。

用户已经明确要求完成整套流程并生成配图时，视为对合理配图的授权，不要在输出分析报告后再次停下来确认；只有图片目标、外部成本或发布版权边界确实不清楚时才询问。目标平台不适合 SVG，或仓库约定使用 PNG 时，保留可编辑源文件并同时导出发布格式。

每张图都检查：标题、中文标签、可读字号、来源脚注、图片类型、替代文字、文件存在和正文引用。

## 阶段七：双视角评审

定稿前完整读取 `references/dual-perspective-review.md`。

至少完成四轮检查：

1. **用户视角**：哪里看不懂、与我无关、像广告、读完不知道怎么做。
2. **作者视角**：哪些不是我的真实判断、承诺是否过头、表达是否像我。
3. **证据视角**：数据是否过期、来源是否支持主张、图片是否误导。
4. **编辑视角**：标题是否重复、术语是否抽象、是否存在 AI 味、上下文是否断裂。

用户选中具体句子要求修改时，只改指定范围及必要衔接；保留用户已经确认的表达，不用整篇重写覆盖人工修改。

## 阶段八：保存交付物

服从目标仓库的落盘规则。在 `kj-llm-wiki` 中：

- 公众号长文默认进入 `raw/studio/funnel/formatted/wechat/`；
- 配图进入文章相邻的 `assets/<date-slug>/`；
- 发布备注可保留证据来源、图片说明、备选标题与转发文案；
- 已发布记录和知识化分别走仓库规定的发布与沉淀流程。

正文完成不等于自动知识化。用户说“沉淀”时，先按目标知识库的本地协议判断它代表捕获还是知识化；在 `kj-llm-wiki` 中，单说“沉淀”默认只触发 Raw 捕获，只有明确说“知识化、整理进 Wiki、形成概念或 SOP”时才创建 Wiki 页面。需要写入个人 Wiki 时可使用 `wiki-doc-sink`，但本地仓库规则优先。不要把 Studio 稿件误写进 Wiki。

## 阶段九：生成下一篇

为当前内容补齐：

- 已发布连接；
- 重复风险；
- 连载位置；
- 可复用的知识库支撑；
- 下一集钩子。

下一篇必须回答本篇自然留下的问题，优先选择续集、方法篇或案例篇，不要用一句空泛的“下篇揭晓”收尾。

## 阶段门禁

### 动笔前

- [ ] 已确认真实读者问题，而不只是作者主题。
- [ ] 已检查本地已有内容和重复风险。
- [ ] 已形成一个核心洞见及其边界。
- [ ] 重要事实已有来源或明确标记待验证。

### 定稿前

- [ ] 每个时效敏感事实已经当前核验。
- [ ] 外部研究、关键数据与配图已有对应关系。
- [ ] 术语已翻译成人话，旧模型/旧年份没有被当成永久结论。
- [ ] 用户视角和作者视角各检查一遍。
- [ ] 图片文件存在、正文链接有效、来源标注准确。

### 交付后

- [ ] 已说明正文、配图和研究材料的实际路径。
- [ ] 已给出知识沉淀决策，不擅自知识化。
- [ ] 已给出下一篇的明确问题和连载关系。

## 输出契约

完整模式默认交付：

1. 核心判断与目标读者；
2. 证据账本或精简来源说明；
3. 可发布正文；
4. 证据—配图对应表与图片文件；
5. 双视角评审后的关键修改；
6. 知识沉淀决策；
7. 下一篇连载卡片。

如果用户只要求最终文章，仍在内部完成门禁，但只展示正文路径和最重要的说明，避免把工作过程变成一份冗长报告。
